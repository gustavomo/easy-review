# Phase 2 — UI Design Contract

> Visual and interaction contract for the AI Review Generation webview panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — VS Code webview CSS custom properties |
| Preset | not applicable |
| Component library | none — plain React 16 with hand-rolled components matching upstream webview patterns |
| Icon library | @vscode/codicons (already a project dependency, used throughout upstream webviews) |
| Font | var(--vscode-font-family) — inherits VS Code editor font, user-configurable |

**Rationale (from CLAUDE.md and codebase scan):** This is a VS Code extension webview, not a web app. The upstream webviews (`webviews/editorWebview`, `webviews/activityBarView`) use VS Code CSS custom properties exclusively — no Tailwind, no shadcn, no design token files. The new ReviewPanel webview must follow the exact same pattern. shadcn is inapplicable here; the runtime is a sandboxed iframe inside VS Code with no npm package resolution, and the tech stack baseline is React 16 (not 18). Do not introduce any external component library.

## Spacing Scale

Declared values (must be multiples of 4). Derived from existing webview CSS (`webviews/editorWebview/index.css`, `webviews/common/common.css`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, reviewer-icons gap, inline badge padding |
| sm | 8px | Button padding (3px 12px inner), textarea padding, section-icon padding, header padding top/bottom |
| md | 16px | Default gap between main sections (#main gap: 16px, #sidebar gap: 16px), section content padding |
| lg | 24px | Section padding when content needs breathing room, collapsible section body padding |
| xl | 32px | Layout horizontal padding (sticky-header: padding 8px 32px), column-gap in grid layouts |
| 2xl | 48px | Not used in upstream webviews — reserve for major panel breaks only |
| 3xl | 64px | Not used in upstream webviews — do not use in Phase 2 |

Exceptions:
- Button border-radius: 4px (established in common.css — use consistently)
- Avatar size: 20×20px (established in common.css)
- Focus outline offset: 1–2px (established in common.css)

Note: `icon-button` padding (2px) and elapsed-time badge horizontal padding (6px) are upstream-inherited values — not re-declared in this spec. Do not introduce new non-multiples-of-4 spacing values.

## Typography

All sizes sourced from `webviews/common/common.css` and upstream component patterns. No custom fonts — always inherit `var(--vscode-font-family)`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 (regular) | 18px (≈1.38 — matches button/textarea baseline in common.css) |
| Label | 11px | 600 (semibold) | 18px (matches .label in common.css) |
| Heading | 16px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

Usage mapping:
- **Body (13px/400):** Streaming output text, review section body content, PR description, error message detail, confirmation dialog body
- **Label (11px/600):** Severity badges (critical/warning/suggestion), model badge in header, state badges, elapsed time counter, history dropdown option text
- **Heading (16px/600):** Each of the 6 collapsible section titles (Executive Summary, Categorized Changes, Key Code Changes, Findings, Impact Analysis, Mermaid), panel PR title
- **Display (20px/600):** ReviewPanel title bar only — reserved for the panel-level heading rendered above the PR title

## Color

This webview uses NO hardcoded hex values. All colors are VS Code CSS custom properties that adapt automatically to light, dark, and high-contrast themes. The 60/30/10 split maps to VS Code token roles.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | var(--vscode-editor-background) | Panel body background, all surface areas, collapsible section backgrounds |
| Secondary (30%) | var(--vscode-panel-background) | Panel header bar, sticky header, code block backgrounds (before/after diff blocks), idle state placeholder area |
| Accent (10%) | var(--vscode-button-background) | Primary Generate Review button only, Retry Review button only |
| Destructive | var(--vscode-list-errorForeground) | Critical severity badge label color, Cancel Generation button label during active generation |

Accent reserved for: **Generate Review button** and **Retry Review button** (error state) only. No other elements use accent. The Cancel Generation button uses `button.secondary` (var(--vscode-button-secondaryBackground)) per the established common.css pattern, not the accent color.

Severity color mapping (from D-24, must match VS Code diagnostic conventions):
- Critical: `var(--vscode-list-errorForeground)` — border + label color on finding cards
- Warning: `var(--vscode-list-warningForeground)` — border + label color on finding cards
- Suggestion: `var(--vscode-editorInfo-foreground)` — border + label color on finding cards

PR state badges (carry forward from Phase 1, D-04 in Phase 1 context):
- Open: `var(--vscode-issues-open)` (green)
- Merged: `var(--vscode-gitDecoration-addedResourceForeground)` or closest purple token — match existing PRTreeItem badge
- Closed: `var(--vscode-list-errorForeground)` (red)

Before/after diff blocks in Key Code Changes section:
- Removed lines: `var(--vscode-diffEditor-removedLineBackground)`
- Added lines: `var(--vscode-diffEditor-insertedLineBackground)`

| Component | File | Description |

| CollapsibleSection | `CollapsibleSection.tsx` | Expandable/collapsible section. Title row with chevron icon, body content slot. Default: all expanded. |
| FindingsSection | `FindingsSection.tsx` | Findings section body. Groups FindingCard components by severity (critical → warning → suggestion). |

| HistoryDropdown | `HistoryDropdown.tsx` | `<select>` element styled per common.css select rules. Options: "Review N (Mon D)" format. |
| ErrorView | `ErrorView.tsx` | Error state. Error message in body typography. Retry Review button (accent). |
| IdleView | `IdleView.tsx` | Idle state. Placeholder copy. No CTA — generation is triggered from the PR tree context menu, not from within the webview. |

**Cancel Generation button clarification:** The Cancel action shown as `[×]` in the layout diagram is an icon+label button with the label "Cancel Generation", not icon-only. Render it as a secondary button with the `codicon-x` icon to the left of the "Cancel Generation" label text. If an icon-only variant is ever used (e.g. in a space-constrained context), it must include `aria-label="Cancel review generation"` on the button element.

**VS Code modal secondary button note:** The re-generate confirmation modal (shown via `vscode.window.showWarningMessage`) includes a "Cancel" secondary button. This button is rendered and labeled by the VS Code API — it is not a webview CTA and is not subject to this spec's copywriting contract. The "Cancel Generation" label above applies exclusively to the webview button that aborts an in-progress generation.

## Interaction Contracts

### State Machine (from D-16)

```
idle → [right-click Generate Review on PR tree item]
     → generating (streaming)
     → complete (review displayed)
     | → error (generation failed or timed out)
     | → idle (user clicked Cancel Generation)
```

Transitions:
- `idle → generating`: Extension host sends `startReview` message with PR metadata. Panel renders StreamingView. Cancel Generation button appears.
- `generating → complete`: Extension host sends `reviewComplete` message with parsed 6-section JSON. Panel renders ReviewDocument. Cancel Generation button disappears.
- `generating → error`: Extension host sends `reviewError` message with error string. Panel renders ErrorView with message and Retry Review button.
- `generating → idle` (cancel): User clicks Cancel Generation. Extension host kills CLI process. Partial output discarded. Panel returns to IdleView.
- `error → generating` (retry): User clicks Retry Review. Same PR re-triggers generation. Transitions as above.
- `complete → generating` (re-generate): Triggered by new right-click on the same PR. Confirmation dialog shown first (see Copywriting below). On confirm, transitions to generating.

### Review History (from D-25)

HistoryDropdown in PanelHeader lists all stored reviews for the current PR in descending creation order. Format: "Review 1 (Apr 3)", "Review 2 (Apr 4)". Selecting a different entry loads that review's `parsed_json` from SQLite via postMessage round-trip. Active selection shows in the dropdown. New reviews are appended to the list after generation.

### Collapsible Sections (from D-23)

All 6 sections start expanded. Clicking the section title row toggles collapse. Collapsed state shows title row only. No accordion constraint — multiple sections can be open simultaneously. Chevron icon: points down when expanded, right when collapsed. Use `@vscode/codicons` `chevron-down` and `chevron-right`.

### Streaming Auto-Scroll (from D-12, D-13)

StreamingView div uses `overflow-y: auto` and `scroll-behavior: smooth`. On each new chunk appended to the streaming content, call `scrollIntoView({ block: 'end' })` on the last text node. Auto-scroll pauses if the user manually scrolls up (detect `scrollTop < scrollHeight - clientHeight - threshold`). Auto-scroll resumes if the user scrolls back to the bottom.

### Elapsed Counter (from D-14)

ElapsedCounter starts a `setInterval(1000)` on mount (when panel enters generating state). Displays integer seconds. Cleared on unmount or state transition out of generating. Format: `"Generating... {N}s"`.

### Confirmation before re-generate (from D-03)

When re-generating a review for a PR that already has reviews, the extension host shows a VS Code confirmation modal via `vscode.window.showWarningMessage`. Not an in-webview dialog. Copy: see Copywriting section below.

## Webview Layout

Panel opens in `vscode.ViewColumn.Two` (beside the code editor). Layout is a single-column scrollable document with a sticky header. No sidebar in the review panel (unlike the PR overview webview which has a grid layout). Follow the same sticky-header pattern from `webviews/editorWebview/index.css`.

```
┌──────────────────────────────────────────────┐
│ [PanelHeader — sticky]                       │
│  PR Title          [model badge] [history ▼] │
│                    [Generating... 45s] [×]   │
├──────────────────────────────────────────────┤
│ [StreamingView | ReviewDocument | Idle | Err]│
│  Scrollable content area                     │
│                                              │
└──────────────────────────────────────────────┘
```

Note: `[×]` in the diagram represents the Cancel Generation button (icon+label). See Component Inventory for the full specification.

PanelHeader height: fixed, approximately 48px (8px top/bottom padding + 16px line-height × 2 rows if needed). Uses `position: sticky; top: 0; z-index: 200` to match existing sticky-header pattern.

Content area: `padding: 16px 32px` to match the horizontal padding established in the editor webview.

**Visual hierarchy per state:**
- Idle state: the placeholder copy ("No review generated yet" heading + instruction body) is the visual anchor. Center it vertically in the content area to draw the user's eye immediately on panel open.
- Generating state: the StreamingView streaming text area dominates the content area as the primary focal point; the ElapsedCounter in PanelHeader is the secondary focal point and must remain visible at all times via the sticky header.
- Complete state: the first CollapsibleSection heading ("Executive Summary") is the primary anchor. It must render at the top of the content area with no preceding whitespace so it is immediately visible on transition from generating.
