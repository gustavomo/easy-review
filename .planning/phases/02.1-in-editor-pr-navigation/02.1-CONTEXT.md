# Phase 2.1: In-Editor PR Navigation - Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the Phase 1 browser-open stub (`vscode.env.openExternal`) with full in-editor PR navigation. When a user clicks a PR in the Easy Review sidebar it expands to show a folder tree of changed files. Clicking any file opens a VS Code diff editor (`vscode.diff`) with before (base commit) and after (head commit) content fetched from the GitHub API. No review generation changes, no UI button additions (Phase 2.2).

</domain>

<decisions>
## Implementation Decisions

### File list structure
- **D-01:** Changed files are shown in a **folder tree** grouped by directory — matching how the upstream GitHub Pull Requests extension presents file changes, not a flat list.
- **D-02:** Each file node shows: filename, change status icon (modified/added/deleted) matching VS Code diagnostic conventions. The diff editor title format: `#<prNumber> <filename>` (per success criteria).

### GitHub API auth strategy
- **D-03:** Use the **upstream Octokit instance** — reuse the GitHub authentication already established by the vscode-pull-request-github fork. No new PAT setting. Works when the user has the upstream extension authenticated.
- **D-04:** `StoredPR.repoId` (`"owner/repo"`) + base/head SHAs from `StoredPR.raw` (full GitHub API response) provide all data needed for file list and content fetch calls.

### Loading UX
- **D-05:** When a PR is expanded and the file list is not yet loaded, show a single **"Loading files..." tree item** with VS Code's `loading~spin` ThemeIcon. Replaced by the folder tree when the API responds.
- **D-06:** File list is fetched fresh on each expansion — no caching in SQLite for Phase 2.1. Caching is deferred.

### Failure experience
- **D-07:** On GitHub API failure (rate limit, auth error, network): show an **error tree item** under the PR ("Failed to load files — click to retry") AND a VS Code error notification with the error reason. The error item is clickable and retries the fetch.
- **D-08:** The error item uses VS Code's `error` ThemeIcon color so it's visually distinct from file items.

### Diff content serving approach
- **D-09:** Use a **simple custom `TextDocumentContentProvider`** registered for an `easy-review-diff://` URI scheme — do NOT attempt to reuse the upstream's `InMemPRFileSystemProvider` or `PullRequestModel`. The upstream tree nodes require a `PullRequestModel` backed by the full `FolderRepositoryManager`/`CredentialStore` stack which Easy Review's `StoredPR` cannot provide. The `easy-review-diff://` provider fetches file content directly from GitHub REST API on demand.
- **D-10:** File list fetched via `GET /repos/{owner}/{repo}/pulls/{pr_number}/files` (returns filenames + change status + base/head SHAs). File content fetched via `GET /repos/{owner}/{repo}/contents/{path}?ref={sha}` for both base and head. All via Octokit with upstream auth (D-03).

### PR overview panel (clicking the PR item)
- **D-11:** Clicking the **PR label** (not the expand arrow) opens a **lightweight PR overview panel** — a new webview using the existing React webview infrastructure from Phase 2. Data comes from `StoredPR.raw` (full GitHub API JSON — no extra API call needed).
- **D-12:** The overview panel shows: PR title, description/body, author, state badge (open/closed/merged), created date, merged date (if applicable), files changed count, additions/deletions, and a "Open on GitHub" link.
- **D-13:** VS Code tree item behavior: when `PRTreeItem` has both a `command` AND `CollapsibleState.Collapsed`, clicking the label runs the command (opens overview), clicking the expand chevron toggles the file tree. Both work independently.
- **D-14:** PR overview panel is a **separate panel** from `ReviewPanel` — not the AI review. Opens in `vscode.ViewColumn.Two` (same as ReviewPanel). Can coexist or replace ReviewPanel if already open.

### Claude's Discretion
- How to hook into the upstream's `CredentialStore` or VS Code authentication session to get an authenticated Octokit instance
- Directory tree node implementation details (recursion, sorting, leaf vs folder distinction)
- Exact `TreeItemCollapsibleState` transitions and `getChildren` implementation for the new tree hierarchy
- URI encoding scheme for `easy-review-diff://` (how to embed owner/repo/sha/path into a URI)
- Whether PR overview panel is a separate `vscode.WebviewPanel` or reuses a singleton pattern like ReviewPanel

</decisions>
