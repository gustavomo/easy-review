# Phase 2.1: In-Editor PR Navigation - Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the Phase 1 browser-open stub (`vscode.env.openExternal`) with full in-editor PR navigation. When a user clicks a PR in the Easy Review sidebar it expands to show a folder tree of changed files. Clicking any file opens a VS Code diff editor (`vscode.diff`) with before (base commit) and after (head commit) content fetched from the GitHub API. No review generation changes, no UI button additions (Phase 2.2).

</domain>

<decisions>
## Implementation Decisions

### File list structure
- **D-01:** Changed files are shown in a **folder tree** grouped by directory — matching how the upstream GitHub Pull Requests extension presents file changes, not a flat list.
- **D-02:** Each file node shows: filename, change status icon (modified/added/deleted) matching VS Code diagnostic conventions. The diff editor title format: `#<prNumber> <filename>` (per success criteria).

### GitHub API auth strategy
- **D-03:** Use the **upstream Octokit instance** — reuse the GitHub authentication already established by the vscode-pull-request-github fork. No new PAT setting. Works when the user has the upstream extension authenticated.
- **D-04:** `StoredPR.repoId` (`"owner/repo"`) + base/head SHAs from `StoredPR.raw` (full GitHub API response) provide all data needed for file list and content fetch calls.

### Loading UX
- **D-05:** When a PR is expanded and the file list is not yet loaded, show a single **"Loading files..." tree item** with VS Code's `loading~spin` ThemeIcon. Replaced by the folder tree when the API responds.
- **D-06:** File list is fetched fresh on each expansion — no caching in SQLite for Phase 2.1. Caching is deferred.

### Failure experience
- **D-07:** On GitHub API failure (rate limit, auth error, network): show an **error tree item** under the PR ("Failed to load files — click to retry") AND a VS Code error notification with the error reason. The error item is clickable and retries the fetch.
- **D-08:** The error item uses VS Code's `error` ThemeIcon color so it's visually distinct from file items.

### Claude's Discretion
- Exact Octokit API calls for fetching file list and file content at specific SHAs (GitHub REST `/repos/{owner}/{repo}/pulls/{pr_number}/files` + `/repos/{owner}/{repo}/contents/{path}?ref={sha}`)
- How to hook into the upstream's `FolderRepositoryManager` or `CredentialStore` to get an authenticated Octokit instance
- Directory tree node implementation details (recursion, sorting, leaf vs folder distinction)
- Whether to use `vscode.diff` directly or wrap via a `TextDocumentContentProvider` scheme (like the upstream's `pr://` scheme)
- Exact `TreeItemCollapsibleState` transitions and `getChildren` implementation for the new tree hierarchy

</decisions>

<specifics>
## Specific Ideas

- The folder tree should match the upstream GitHub Pull Requests extension UX — that's the reference the user is comparing against ("like the GitHub Pull Requests plugin")
- Diff editor title: shows PR number and filename (required by success criteria NAV-02)

</specifics>

### Reusable Assets
- `src/view/treeNodes/fileChangeNode.ts` `openDiffCommand()` — Opens vscode.diff with two URIs; can likely be reused or adapted
- `src/view/inMemPRContentProvider.ts` `InMemPRFileSystemProvider` — Content provider infrastructure for serving file bytes to diff editors

### Established Patterns
- Upstream uses `vscode.diff` command with custom URI schemes (`pr://`) for diff editors — Easy Review should follow the same pattern rather than inventing a new URI scheme
- `EasyReviewPRsProvider.getChildren(element)` returns `[]` when `element` is set (flat list). Must change to return file/directory nodes when element is a `PRTreeItem`.
- `PRTreeItem` currently has `TreeItemCollapsibleState.None` — must become `Collapsible` to support expansion

### Integration Points
- `easy-review.openPRDiff` command in `activation.ts:69` — this is the stub being replaced
- `EasyReviewPRsProvider.getChildren()` — needs new hierarchy: PR → directories → files
- Upstream's `FolderRepositoryManager` or `CredentialStore` needed to get authenticated Octokit

</code_context>
