# Phase 02.2 Plan 02: package.json commands + menu contributions, activation.ts store injection + command registrations Summary

Wired the Phase 2.2 TypeScript layer (from Plan 01) into the VS Code contribution system: two new commands declared in package.json (easy-review.viewReview with $(eye), easy-review.openSettings with $(settings-gear)), three view/title buttons added for the sidebar title bar (navigation@1/2/3), one inline view/item/context button for "View Review" conditional on `viewItem =~ /hasReview/`, store injected into EasyReviewPRsProvider at construction, and post-review refreshPRContextValue hook added so the eye button appears immediately after generating a review.

## What Was Built

### Task 1: package.json command declarations and menu contributions

**contributes.commands** — two new entries appended after `easyReview.viewAnalysis`:
- `easy-review.viewReview`: title "View Review", icon `$(eye)`
- `easy-review.openSettings`: title "Open Easy Review Settings", icon `$(settings-gear)`

**contributes.menus["view/title"]** — three new entries added before the existing refreshPRList/addPRByUrl entries:
- `easyReview.viewAnalysis` at `navigation@1` (book icon, leftmost)
- `easyReview.analyzePRHistory` at `navigation@2` (history icon, center)
- `easy-review.openSettings` at `navigation@3` (settings-gear icon, rightmost)

All three scoped with `when: "view == easy-review.prList"`.

**contributes.menus["view/item/context"]** — one new inline entry added before the existing generateReview entry:
- `easy-review.viewReview` with `when: "view == easy-review.prList && viewItem =~ /hasReview/"`, `group: "inline"`

The `/hasReview/` regex matches `pr-open-hasReview`, `pr-closed-hasReview`, and `pr-merged-hasReview` contextValues set by PRTreeItem from Plan 01.

### Task 2: activation.ts command registrations, store injection, post-review hook

**Store injection** (line 51):
- Changed `new EasyReviewPRsProvider()` to `new EasyReviewPRsProvider(undefined, store)`
- `undefined` first arg preserves the existing `setCredentialStore()` injection pattern (line 55)

**Post-review refresh hook** (in generateReview handler, after `await panel.startReview()`):
- `getProvider()?.refreshPRContextValue(item.pr.repoId, item.pr.prNumber)` — called after startReview resolves, ensuring the review is saved before querying getReviews

**easy-review.viewReview command** (new, after generateReview):
- Guards: `!currentStore || !item?.pr` → return
- `currentStore.getReviews(item.pr.repoId, item.pr.prNumber)` — fetch all reviews
- Sorts by `createdAt` descending — latest first
- `ReviewPanel.getOrCreate(context, currentStore)` → `panel.loadReview(latest)`

**easy-review.openSettings command** (new, after viewReview):
- `vscode.commands.executeCommand('workbench.action.openSettings', 'easyReview')` — filters to entire easyReview namespace
