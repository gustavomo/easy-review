# Phase 02.2 — Sidebar UI Enhancements — Context

<domain>
Add visible action buttons to the Easy Review sidebar:
- A PR-level inline "View Review" button (eye icon) that opens the ReviewPanel pre-loaded with the latest stored review
- Three title bar buttons: View Project Analysis, View PR History Analysis, and Settings

No new commands need to be created — all backing commands (easyReview.analyzeProject, easyReview.analyzePRHistory, easyReview.viewAnalysis, workbench.action.openSettings) are already registered. This phase is entirely package.json contribution points + a new `easy-review.viewReview` command wired to the ReviewPanel.
</domain>

<decisions>
## Implementation Decisions

### "View Review" button — visibility
- **D-01:** The inline "View Review" button is **hidden when a PR has no stored review**. It only appears when the PR has at least one stored review.
  - Implementation: use two `contextValue` variants on `PRTreeItem` — e.g., `pr-open-hasReview` vs `pr-open` — and `when` clause in package.json matches `viewItem =~ /hasReview/`.
  - `PRTreeItem` constructor must check `store.getReviews(pr.repoId, pr.prNumber).length > 0` and set the appropriate contextValue. This requires passing the store to `PRTreeItem` or computing contextValue after-the-fact in `EasyReviewPRsProvider`.

### "View Review" button — icon
- **D-02:** Use `$(eye)` codicon — universally means "view", and is distinct from the `$(sparkle)` Generate Review button already on the same row.

### "View Review" button — behavior with multiple reviews
- **D-03:** "View Review" opens the ReviewPanel **pre-loaded with the most recently created review** (highest `createdAt` timestamp). The existing Phase 2 history dropdown (VIEW-03) in the ReviewPanel handles browsing older review versions — no new UI needed for multi-review navigation.

### "View Review" — ReviewPanel entry point
- **D-04:** A new command `easy-review.viewReview` is registered. It receives a `StoredPR` argument, queries `store.getReviews(pr.repoId, pr.prNumber)`, takes the latest, and calls `ReviewPanel.getOrCreate(context, store).loadReview(review)`.
  - `ReviewPanel` needs a new `loadReview(review: StoredReview)` public method (or adapt `startReview` path) that loads an existing review into the complete state without generating a new one.
  - The message path already exists: `postMessage({ type: 'loadReviewResult', review: parsedReview })` — `loadReview()` just needs to call `updateState` + `postMessage` directly.

### Title bar buttons
- **D-05:** Three buttons added to `view/title` for `view == easy-review.prList`, all in `navigation` group:
  1. `easyReview.viewAnalysis` — icon `$(book)` — View Project Analysis
  2. `easyReview.analyzePRHistory` — icon `$(history)` — View PR History Analysis
  3. A new `easy-review.openSettings` command — icon `$(settings-gear)` — executes `workbench.action.openSettings` with `easyReview` query
- Order in the title bar is right-to-left for `navigation` group items in VS Code, so registration order in package.json should be: settings (last = leftmost visible), history, analysis — or use `navigation@1`, `navigation@2`, `navigation@3` to control order explicitly.

### Settings button
- **D-06:** A new command `easy-review.openSettings` executes `vscode.commands.executeCommand('workbench.action.openSettings', 'easyReview')`. Simple wrapper — one line in activation.ts.
</decisions>

<specifics>
## Specific Details

- The upstream GitHub Pull Requests extension is the visual reference for tree item inline buttons — use the same `group: "inline"` pattern already used by `easyReview.generateReview`.
- `PRTreeItem.contextValue` currently = `pr-open`, `pr-closed`, or `pr-merged`. Phase 2.2 adds `-hasReview` suffix variants: `pr-open-hasReview`, `pr-closed-hasReview`, `pr-merged-hasReview`. The `easyReview.generateReview` `when` clause uses `viewItem =~ /^pr-/` — this regex still matches with the suffix, so no breaking change to existing button.
- The ReviewPanel's existing history dropdown already handles multiple reviews per PR (VIEW-03 from Phase 2) — no new webview UI work required.
</specifics>
