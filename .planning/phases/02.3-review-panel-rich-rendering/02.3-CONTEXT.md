# Phase 02.3: Review Panel Rich Rendering - Context

**Gathered:** 2026-04-04 (updated 2026-04-03)
**Status:** Ready for planning

<domain>
## Phase Boundary

Upgrade the review webview panel to render content inside sections with proper visual
treatment. This includes:
- Syntax highlighting for code blocks (all sections)
- Mermaid source rendered as SVG diagrams
- Dedicated visual components for **Categorized Changes** and **Impact Analysis** sections
- Markdown table CSS styles

Layout, collapsible section structure, streaming, and the Findings section are out of scope.

</domain>

<decisions>
## Implementation Decisions

### Syntax highlighting library
- **D-01:** Use **highlight.js** — integrate via marked's `highlight` callback option.
- **D-02:** Apply to ALL markdown sections globally (Executive Summary, Architecture,
  Findings body, every section). One global callback on `marked` config — no per-section
  logic.
- **D-03:** Auto-detect language when fenced code block has no language tag.
- **D-04:** Style with highlight.js CSS vars mapped to VS Code theme colors (not hardcoded
  colors). Use `--vscode-editor-foreground`, `--vscode-textCodeBlock-background` etc.
  Avoid importing a hljs theme CSS directly — it would override VS Code theming.

### Mermaid rendering
- **D-05:** Full SVG rendering via **mermaid.js** bundled into the webview.
- **D-06:** The dedicated Mermaid section (`isMermaidSection` in ReviewDocument.tsx)
  renders as a live SVG diagram. The current "coming in a future version" note is removed.
- **D-07:** Mermaid needs `unsafe-eval` in the CSP `script-src` directive (it uses `eval`
  internally). Update `getWebviewHtml()` in ReviewPanel.ts to add `'unsafe-eval'` to
  `script-src` for the mermaid use case.
- **D-08:** Mermaid theme: use `'dark'` or `'neutral'` — detect from VS Code's active
  color theme if possible (check `document.body.className` for `vscode-dark` / `vscode-light`),
  otherwise default to `'dark'`.
- **D-09:** Render errors (invalid diagram syntax) show a styled error message in place of
  the diagram — do not crash the whole section.

### Categorized Changes section
- **D-10:** Add a dedicated `CategorizedChangesSection` component (parallel to
  `FindingsSection`). Detected by title match: `section.title.toLowerCase().includes('categorized')`.
- **D-11:** Visual layout — **category chips + bullet items**. Each change category (Feature,
  Refactor, Bug Fix, Test, Docs, etc.) gets a colored chip/badge header followed by bullet
  items below it. Scannable at a glance.
- **D-12:** Chip color scheme — **semantic colors** using VS Code CSS vars:
  - Feature → blue (`--vscode-charts-blue` or similar)
  - Bug Fix → red (`--vscode-charts-red`)
  - Refactor → purple (`--vscode-charts-purple`)
  - Test → green (`--vscode-charts-green`)
  - Docs → gray (`--vscode-descriptionForeground`)
  - Unknown/Other → neutral accent (`--vscode-badge-background`)
- **D-13:** Parse the markdown content to extract category headers (### headings) and their
  bullet items. If parsing fails, fall back to generic `marked()` rendering.

### Impact Analysis section
- **D-14:** Add a dedicated `ImpactAnalysisSection` component. Detected by title match:
  `section.title.toLowerCase().includes('impact')`.
- **D-15:** Visual layout — **impact level badges + styled dimension sections**. Each
  dimension (Performance, Security, Breaking Changes, etc.) gets a styled header. Impact
  levels (High/Medium/Low) detected in content and shown as colored badges inline.
- **D-16:** Impact badge colors (same semantic pattern as Findings severity):
  - High → red
  - Medium → yellow/orange
  - Low → blue/green
- **D-17:** **Breaking Changes get a warning banner** — if the section contains a
  "Breaking Changes" dimension with High impact, show a distinct orange/red warning
  banner at the top of the Impact Analysis section (before other dimensions).
- **D-18:** If parsing fails to detect structure, fall back to generic `marked()` rendering.

### Markdown table CSS
- **D-19:** Add table styles to `.easy-review-md` in `webview.css`. Applies globally to any
  table Claude generates in any section.
- **D-20:** Style: **striped rows + bordered cells**. Alternating row background using
  `--vscode-list-hoverBackground` for odd rows. Header row uses
  `--vscode-editorGroupHeader-tabsBackground` with bold text. Cell borders use
  `--vscode-panel-border`.

### Claude's Discretion
- Exact highlight.js CSS overrides for token colors
- Whether to lazy-load mermaid (import on first render) or eager-load
- Exact error UI for mermaid render failures
- Exact VS Code CSS var mappings for chip/badge colors (choose closest available vars)
- Whether `CategorizedChangesSection` and `ImpactAnalysisSection` parse markdown internally
  or receive pre-parsed data from ReviewParser.ts

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `marked` (already installed) — used in ReviewDocument.tsx for all section markdown.
  highlight.js integrates via `marked.setOptions({ highlight: ... })` or
  `marked.use({ hooks: { ... } })` depending on marked version.
- `.easy-review-md` CSS class — applied to all markdown divs; any hljs token colors and
  table styles scoped inside this class avoid polluting other webview content.
- `FindingsSection.tsx` — pattern to follow for `CategorizedChangesSection` and
  `ImpactAnalysisSection`. Check how it parses content and renders severity badges.

### Established Patterns
- VS Code CSS vars (`--vscode-*`) used throughout for theming — chip/badge colors must
  follow this pattern, not use hardcoded hex values.
- `dangerouslySetInnerHTML={{ __html: marked(content) }}` — current render path; any
  section with a dedicated component bypasses this path entirely.
- Title-based section detection (`isFindingsSection`, `isMermaidSection`) — extend this
  pattern in ReviewDocument.tsx for `isCategorizedSection` and `isImpactSection`.

### Integration Points
- `ReviewDocument.tsx` main render switch → add `isCategorizedSection` and `isImpactSection`
  branches before the generic `dangerouslySetInnerHTML` fallback.
- `ReviewPanel.ts` CSP string → add `'unsafe-eval'` to script-src.
- `vite.config.ts` → mermaid may need dynamic import to control bundle splitting.

</code_context>
