## Spacing Scale

All spacing values are multiples of 4. Existing `webview.css` and `FindingCard.tsx` establish the project baseline — this phase extends it, does not override it.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge padding (vertical), icon gaps |
| sm | 8px | Card padding (vertical), item margins, mermaid error padding |
| md | 16px | Card padding (horizontal), section element spacing, list indent |
| lg | 24px | Category group bottom margin |
| xl | 32px | Major section internal breaks |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- `pre code` blocks: `padding: 12px 16px` (already established in `webview.css` — do not change)
- `FindingCard` left border: `3px solid {color}` (already established — follow same 3px pattern for category chips)
- Table cells: `padding: 6px 12px` (new — D-20; 6px vertical chosen to keep rows compact at 13px font size)

**Source:** Existing `FindingCard.tsx` (8px vertical, 16px horizontal), existing `webview.css` (12px/16px pre padding). All new values follow the established scale.

## Typography

This phase does not introduce new font sizes or weights. All type specifications below are pre-existing project standards carried from `FindingCard.tsx` and `webview.css`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13px | 400 | 1.6 | Markdown prose in `.easy-review-md`, bullet items in `CategorizedChangesSection`, dimension content in `ImpactAnalysisSection` |
| Label | 11px | 600 | 1.0 | Category chip labels (uppercase), impact badge labels (uppercase), severity badge labels — matches `FindingCard.tsx` badge pattern |
| Code | 12px | 400 | 1.5 | Code blocks in `pre code`, inline `code` elements — already in `webview.css` |
| Heading (section-internal) | 13px | 600 | 1.2 | `### heading` equivalents inside `CategorizedChangesSection` and `ImpactAnalysisSection` dimension headers — matches existing `.easy-review-md h3` rule |

Font declaration: Only 3 distinct sizes (13px body/heading, 12px code, 11px label) and 2 weights (400 regular, 600 semibold). No new sizes introduced.

**Source:** `FindingCard.tsx` (11px/600 badge, 13px/400 body), `webview.css` (.easy-review-md: 13px/1.6 body; pre code: 12px/1.5).

## Color

All colors use VS Code CSS custom properties — no hardcoded hex values. The 60/30/10 split maps to VS Code's theme layers.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--vscode-editor-background)` | Card backgrounds (`FindingCard`, `CategorizedChangesSection` chips, `ImpactAnalysisSection` dimension blocks) |
| Secondary (30%) | `var(--vscode-textCodeBlock-background)` | `pre` code block backgrounds, table header row background (`--vscode-editorGroupHeader-tabsBackground`) |
| Accent (10%) | See Accent Map below | Chips, badges, borders — each reserved for specific element only |
| Destructive | `var(--vscode-list-errorForeground)` + `var(--vscode-inputValidation-errorBackground)` + `var(--vscode-inputValidation-errorBorder)` | Mermaid render error container; Breaking Changes warning banner |

**Accent Map — reserved elements only (D-12, D-16, D-20):**

| Accent Color | VS Code Variable | Reserved For |
|-------------|-----------------|--------------|
| Blue | `var(--vscode-charts-blue)` | Feature category chip only |
| Red | `var(--vscode-charts-red)` | Bug Fix category chip; High impact badge only |
| Purple | `var(--vscode-charts-purple)` | Refactor category chip only |
| Green | `var(--vscode-charts-green)` | Test category chip; Low impact badge only |
| Gray | `var(--vscode-descriptionForeground)` | Docs category chip only |
| Neutral badge | `var(--vscode-badge-background)` | Unknown/Other category chip only |
| Yellow/Orange | `var(--vscode-list-warningForeground)` | Medium impact badge; Breaking Changes warning banner border only |
| Blue/Teal | `var(--vscode-editorInfo-foreground)` | Low impact badge (alternative to green if charts-green absent) |

**Table colors (D-20):**
- Odd row stripe: `var(--vscode-list-hoverBackground)` — applies to `tr:nth-child(odd)` within `tbody`
- Header row: background `var(--vscode-editorGroupHeader-tabsBackground)`, text `var(--vscode-editor-foreground)` at weight 600
- Cell borders: `var(--vscode-panel-border)`

**Mermaid diagram container:** inherits `var(--vscode-editor-background)`; SVG rendered inline via `dangerouslySetInnerHTML`. No border or additional background on the diagram container itself.

**Source:** CONTEXT.md D-12, D-16, D-17, D-20; RESEARCH.md Pattern 3; existing `FindingCard.tsx` severity color map.

## Component Inventory

New components introduced in this phase. All follow the `FindingCard.tsx` inline-style pattern — no CSS modules, no external class names beyond `.easy-review-md` scope.

### 1. `MermaidDiagram` component

**Location:** `src/webview/MermaidDiagram.tsx` (new file)

**States:**

| State | Visual Treatment |
|-------|-----------------|
| Loading | Single line: `"Rendering diagram..."` at 12px, `var(--vscode-descriptionForeground)` |
| Rendered | Inline SVG via `dangerouslySetInnerHTML={{ __html: svg }}`, no wrapper styling |
| Error (D-09) | Container: background `var(--vscode-inputValidation-errorBackground)`, border `1px solid var(--vscode-inputValidation-errorBorder)`, border-radius 4px, padding 8px 12px. Text: `"Mermaid render error: {message}"` at 12px, `var(--vscode-list-errorForeground)` |

**Theme detection (D-08):** Check `document.body.classList` for `vscode-dark` or `vscode-high-contrast` at module initialization → pass `theme: 'dark'` to `mermaid.initialize`. Otherwise pass `theme: 'default'`.

**Init options:** `startOnLoad: false`, `securityLevel: 'loose'` (required for CSP with `unsafe-eval`).

### 2. `CategorizedChangesSection` component

**Location:** `src/webview/CategorizedChangesSection.tsx` (new file)

**Detection:** `section.title.toLowerCase().includes('categorized')` in `ReviewDocument.tsx`

**Layout:** For each parsed category (D-11, D-13):
- Category chip: inline-block, background `{categoryColor}` at 15% opacity, border `1px solid {categoryColor}`, border-radius 12px, padding 2px 10px, margin-bottom 8px
- Chip label: 11px, weight 600, color `{categoryColor}`, `textTransform: 'uppercase'`
- Bullet list: `margin: 0 0 16px 0`, `paddingLeft: 16px`. Each `<li>` at 13px/400/1.6 in `var(--vscode-editor-foreground)`
- Category group spacing: `marginBottom: 16px` between groups

**Fallback (D-13):** When `### headings` cannot be parsed from content, render `<div dangerouslySetInnerHTML={{ __html: marked(content) }} className="easy-review-md" />`

**Background opacity for chips:** Since VS Code CSS vars are not hex values, use a wrapper `<span>` with the border-color var and a separate `background` approach. Practical implementation: set `background` to `color-mix(in srgb, {categoryColor} 15%, transparent)` — supported in modern Chromium (VS Code uses Electron/Chromium). If `color-mix` is unavailable, fall back to `background: var(--vscode-badge-background)`.

### 3. `ImpactAnalysisSection` component

**Location:** `src/webview/ImpactAnalysisSection.tsx` (new file)

**Detection:** `section.title.toLowerCase().includes('impact')` in `ReviewDocument.tsx`

**Warning banner (D-17):** Rendered FIRST inside the component when "Breaking Changes" dimension with High impact is detected.
- Container: background `var(--vscode-inputValidation-warningBackground, rgba(200,100,0,0.12))`, border-left `3px solid var(--vscode-list-warningForeground)`, border-radius `0 4px 4px 0`, padding `8px 16px`, margin-bottom `16px`
- Label: `"Breaking Changes"` at 11px, weight 600, `var(--vscode-list-warningForeground)`, uppercase
- Body: detected breaking changes bullet content at 13px/400

**Dimension block layout (D-15):**
- Dimension header: 13px, weight 600, `var(--vscode-editor-foreground)`, margin-bottom 4px
- Impact badge (inline): 11px, weight 600, uppercase. Colors per D-16:
  - High: background `color-mix(in srgb, var(--vscode-charts-red) 15%, transparent)`, border `1px solid var(--vscode-charts-red)`, color `var(--vscode-charts-red)`
  - Medium: background `color-mix(in srgb, var(--vscode-list-warningForeground) 15%, transparent)`, border `1px solid var(--vscode-list-warningForeground)`, color `var(--vscode-list-warningForeground)`
  - Low: background `color-mix(in srgb, var(--vscode-charts-green) 15%, transparent)`, border `1px solid var(--vscode-charts-green)`, color `var(--vscode-charts-green)`
- Badge padding: 1px 8px, border-radius 10px, margin-left 8px (inline after dimension title)
- Dimension body content: 13px/400 in `var(--vscode-editor-foreground)`

**Fallback (D-18):** When parsing fails, render `<div dangerouslySetInnerHTML={{ __html: marked(content) }} className="easy-review-md" />`

## Interaction Contract

### Mermaid diagram

- Renders in a `useEffect` on first mount; shows loading placeholder during async render.
- On error: replaces placeholder with error container. Does not affect other sections.
- No click, zoom, or pan interactions in this phase (deferred to future phases).
- SVG is injected as raw HTML — no interactive SVG elements expected from the Mermaid diagram source.

### CategorizedChangesSection

- Static render only — no expand/collapse in this phase (collapsible section structure is out of scope per CONTEXT.md domain boundary).
- Fallback to `marked()` output is silent — no indicator shown to user.

### ImpactAnalysisSection

- Warning banner is rendered unconditionally when the Breaking Changes + High impact condition is met — no dismiss/close affordance.
- Static render only.

### Table

- Striped rows are presentational only — no row selection or interaction.
- `overflow-x: auto` on the `<table>` wrapper to handle wide tables inside the webview panel.

### Syntax highlighting

- Applied globally to all `marked()` output via `marked-highlight` plugin — no per-section toggle.
- Language auto-detection (D-03): when fenced block has no language tag, `hljs.highlightAuto()` is used.

## CSP Change

`ReviewPanel.ts` → `getWebviewHtml()` must add `'unsafe-eval'` to the `script-src` CSP directive to allow mermaid.js to execute. This is a security-sensitive change — document in the plan task explicitly.

**Source:** CONTEXT.md D-07; RESEARCH.md Pattern 2.

## Bundle Impact

Mermaid adds ~2–3MB to the webview bundle after Vite tree-shaking (from ~75MB unpacked). Vite config must set `chunkSizeWarningLimit: 3500` (kB) and use `manualChunks` to consolidate mermaid into a single chunk to avoid dynamic import splitting errors under VS Code's CSP.

**Source:** RESEARCH.md Summary paragraph.
