#### 1. Syntax Highlighting — Runtime Token Classes

**Test:** Open a PR review in VS Code Extension Development Host. Open a review section with a code block. Right-click on the code block, choose "Inspect Element".
**Expected:** `<code>` element has classes like `hljs language-typescript` (or auto-detected language). Child elements are `<span class="hljs-keyword">`, `<span class="hljs-string">`, etc. with visible color differences matching VS Code theme.
**Why human:** hljs class application requires the browser to process the `markedHighlight` callback at runtime. Grep confirms the wiring but cannot verify the HTML output.

#### 2. Mermaid SVG Diagram — Live Render

**Test:** Open a PR review that has a Mermaid Architecture Diagram section. Observe the section content.
**Expected:** A rendered SVG diagram (flowchart, sequence diagram, or similar) is visible — not a `<pre>` code block and not "coming in a future version" text.
**Why human:** `mermaid.render()` is async and requires a real DOM with `unsafe-eval` enabled. Cannot verify SVG output without running the webview.

#### 3. Category Chips — Visual Appearance

**Test:** Open a PR review with a Categorized Changes section. Observe the section.
**Expected:** Each change category (e.g., "FEATURE", "REFACTOR") appears as a colored rounded pill/chip. Items under each category appear as a bullet list below the chip. Chip background is a translucent version of its border color (color-mix).
**Why human:** CSS `color-mix()` and VS Code var rendering requires a live browser context.

#### 4. Categorized Changes Fallback

**Test:** Trigger a review where the AI produces a Categorized Changes section without `###` headings (unlikely but possible with prompt variation). Or temporarily modify a stored review's `categorized_changes` content to remove headings.
**Expected:** Section renders as standard markdown (no chips), not an empty div or error.
**Why human:** Requires runtime data matching the fallback trigger condition.

#### 5. Breaking Changes Warning Banner

**Test:** Open a PR review whose Impact Analysis section has a "Breaking Changes" dimension with "High" impact content.
**Expected:** An orange warning banner labeled "BREAKING CHANGES" appears at the top of the Impact Analysis section, above all dimension blocks.
**Why human:** Requires matching review data with specific content structure.

#### 6. Markdown Table Rendering

**Test:** Open a PR review section that contains a markdown table (e.g., in the Impact Analysis or Executive Summary). Observe the table.
**Expected:** Table has bordered cells, alternating gray/transparent row backgrounds, and a bold header row with distinct background.
**Why human:** CSS rendering verification requires a live browser.

#### 7. Mermaid Dark/Light Theme

**Test:** Switch VS Code to a light theme, then open a review with a Mermaid section. Observe diagram colors.
**Expected:** Diagram uses mermaid's 'default' (light) theme. In dark theme, diagram uses 'dark' theme.
**Why human:** `document.body.classList` detection requires a live VS Code webview session.
