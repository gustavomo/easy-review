## Spacing Scale

Declared values (must be multiples of 4). Source: measured from existing components in `PanelHeader.tsx`, `FindingCard.tsx`, `CollapsibleSection.tsx`, `ImpactAnalysisSection.tsx`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline padding within badges |
| sm | 8px | Compact element spacing, vertical padding in cards, section title row padding |
| md | 16px | Default element spacing, card body padding, CollapsibleSection child indent |
| lg | 24px | CollapsibleSection left-indent for body content |
| xl | 32px | Horizontal panel padding (PanelHeader uses `padding: '8px 32px'`) |
| 2xl | 48px | Not currently used; available for major section breaks |
| 3xl | 64px | Not currently used; available for page-level spacing |

Exceptions:
- Agent status badge pill padding: `4px 8px` (standard minimum vertical for compact inline badges — uses `xs` token; note that the existing impact badge pattern in `ImpactAnalysisSection.tsx` uses a non-grid `1px` vertical value which should be reconciled to `4px` during Phase 6 implementation)
- Section title row: `padding: '8px 0'` (no horizontal padding on the button itself — inherited from CollapsibleSection)
- PanelHeader sticky bar height: ~48px total (8px top + 8px bottom padding + 13px font + line height)

## Interaction Contracts

### Progressive Section Rendering

- Sections render in display order (PR Summary first, Business Impact last) regardless of agent completion order.
- A section that has not yet completed renders `SectionPendingPlaceholder` inside an expanded `CollapsibleSection`.
- When an agent completes, its `SectionState` transitions to `complete` and the placeholder is replaced with the real renderer — no page scroll jump (use stable section heights or minimum height on placeholder to reduce reflow).
- If an agent errors, its slot shows `SectionErrorPlaceholder` with the error message and a "Retry Agent" button.

### AgentStatusBar Interaction

- The bar is read-only during generation — no interactive elements except for individual "Retry Agent" buttons on errored slots (if retry is in scope for Phase 6 — planner confirms).
- Each `AgentSlot` chip has `title` attribute with agent name and current state for hover tooltip (no custom tooltip component needed).
- On all-agents-complete, the bar transitions from mixed states to all-green and the PanelHeader elapsed counter stops.

### Mermaid Self-Correction Feedback (D-16 to D-18)

- During retry attempts (up to 2), the Visual Overview section shows `SectionPendingPlaceholder` with copy "Validating diagram..." (not the generic "Generating..." copy).
- After 2 failed retries, the section shows `DiagramErrorBanner` above the raw Mermaid code block rendered as a plain code block.
- The `DiagramErrorBanner` is not dismissible — it remains visible for the session.

### Cancel Generation

- "Cancel Generation" button (existing in PanelHeader) cancels all 7 agents simultaneously.
- Already-completed sections remain rendered (progressive results are not discarded).
- The `AgentStatusBar` shows completed slots as green and pending/generating slots as grey (cancelled state — same visual as pending is acceptable).

### Collapsible Sections

- All 7 sections start expanded (matches existing `defaultExpanded={true}` default).
- Collapsing a section that is still generating hides the spinner but does not cancel that agent.

## Implementation Notes for Executor

1. **Inline styles only** — no CSS Modules, no new CSS files unless adding to `webview.css`. This matches every existing component in `src/webview/`.

2. **No new color values** — all colors must be VS Code CSS custom properties from the palette defined above. The single exception: highlight.js token colors in `webview.css` are already hardcoded and must not be changed.

3. **`color-mix(in srgb, {var} 15%, transparent)`** — use this pattern for tinted badge backgrounds (established in `ImpactAnalysisSection.tsx`).

4. **Codicon class names for all icons** — `codicon-clock`, `codicon-loading`, `codicon-check`, `codicon-error`, `codicon-warning`. The `codicon-loading` spin animation is already declared in `StreamingView.tsx` as `@keyframes er-spin` — extract to `webview.css` or replicate inline.

5. **React 16 / `ReactDOM.render`** — do not use `createRoot`. The webview entry point uses React 16 API.

6. **No fetch() in webview** — VS Code CSP blocks it. All model-selection data comes from extension host via postMessage.

7. **Section state updates via postMessage** — Phase 6 adds `sectionUpdate` message type to `ExtensionMessage` in `src/shared/types.ts`. The webview receives these and updates its `Record<AgentKey, SectionState>` map. The exact message shape is defined by the planner.
