# Phase 7 — UI Design Contract

> Visual and interaction contract for the Changes Tree Enhancements phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — VS Code native TreeView API only |
| Icon library | VS Code active file icon theme (ThemeIcon.File) + GitHub avatar HTTPS URIs |
| Font | VS Code UI font (inherited from editor, not customizable by extensions) |

**Note:** This phase modifies zero webview components, zero CSS files, and zero React components. All visual changes are expressed through VS Code TreeItem API properties (`iconPath`, `description`, `resourceUri`). The standard UI-SPEC categories (spacing, typography, color, registry) do not apply in the traditional sense. Each section below maps VS Code TreeItem contracts instead.

## Color

VS Code TreeView colors are inherited from the active theme. This phase does not introduce custom colors.

| Role | Value | Usage |
|------|-------|-------|
| File label color (added) | `var(--vscode-gitDecoration-addedResourceForeground)` | Green label on added files — driven by existing `FileTypeDecorationProvider` via `resourceUri` query params |
| File label color (deleted) | `var(--vscode-gitDecoration-deletedResourceForeground)` | Red label on deleted files — same mechanism |
| File label color (modified) | `var(--vscode-gitDecoration-modifiedResourceForeground)` | Orange label on modified files — same mechanism |
| PR state text in description | Inherited from `var(--vscode-descriptionForeground)` | Dimmed secondary text, VS Code default for TreeItem.description |

**No new colors introduced.** File label coloring is preserved by keeping the existing `FileChange://` scheme `resourceUri` unchanged (D-03 resolution from RESEARCH.md). The upstream `FileTypeDecorationProvider` (registered globally) continues to provide color/badge decorations.

Accent reserved for: not applicable (no custom accent colors in TreeView)

## Icon Contract

This section replaces the standard Color/Spacing/Typography sections as the primary visual contract for this phase.

### FileNode Icon (D-01, D-02, D-03)

| Property | Before | After |
|----------|--------|-------|
| `iconPath` | `new vscode.ThemeIcon(FILE_STATUS_ICON[file.status])` | `vscode.ThemeIcon.File` |
| Icon appearance | Generic diff codicon (diff-added, diff-removed, diff-modified) | File-type icon from active icon theme (TypeScript, JSON, CSS, etc.) |
| `resourceUri` | `toResourceUri(vscode.Uri.file(file.filename), ...)` with `FileChange://` scheme | **Unchanged** — preserves label color decorations |

**Implementation:** Single-line change. Set `this.iconPath = vscode.ThemeIcon.File`. VS Code resolves the file-type icon by reading the file extension from `resourceUri.path`. The `FILE_STATUS_ICON` map becomes unused and should be removed as dead code.

**Why this works:** VS Code icon resolution reads the path component of `resourceUri` for file extension matching, regardless of URI scheme. The `FileChange://` scheme is only read by `FileTypeDecorationProvider` for color/badge decorations. Verified in upstream `src/view/treeNodes/fileChangeNode.ts:111` which uses the same pattern.

### PRTreeItem Icon (D-04, D-05, D-06)

| Property | Before | After (avatar available) | After (fallback) |
|----------|--------|--------------------------|-------------------|
| `iconPath` | `new vscode.ThemeIcon(icon.id, icon.color)` | `vscode.Uri.parse(avatarUrl + '?s=40')` | `new vscode.ThemeIcon(icon.id, icon.color)` (same as before) |
| Icon appearance | State-colored codicon (green git-pull-request, purple git-merge, red git-pull-request-closed) | Author's GitHub avatar (40x40 from CDN) | State-colored codicon (unchanged) |

**Avatar URL extraction:**
- Source: `StoredPR.raw` field (JSON string of full GitHub API PR response)
- Field path: `JSON.parse(pr.raw).user.avatar_url`
- Size parameter: Append `?s=40` to avatar URL (or `&s=40` if URL already has query params) for a 40x40 image. GitHub CDN supports this parameter. Reduces bandwidth vs default 460x460.
- Fallback: If `user.avatar_url` is absent, null, empty string, or `JSON.parse` throws, fall back to the current state-colored ThemeIcon. Never show a broken/missing image.

### DirectoryNode Icon

**Unchanged.** `new vscode.ThemeIcon('folder')` remains as-is. Not in scope per CONTEXT.md.

### LoadingNode and ErrorNode Icons

**Unchanged.** Not in scope.

## Copywriting Contract

| Element | Copy |
|---------|------|
| PR description format | `{state} \u00b7 @{author}` — e.g., `open \u00b7 @gustavo`, `merged \u00b7 @alice`, `closed \u00b7 @bob` |
| Separator character | Middle dot `\u00b7` (U+00B7) — lightweight, visually distinct from both state and author text |
| State text | Lowercase: `open`, `closed`, `merged` — matches `StoredPR.state` values directly, no transformation needed |
| Empty state heading | not applicable — no new empty states introduced |
| Empty state body | not applicable |
| Error state | not applicable — no new error states introduced |
| Destructive confirmation | not applicable — no destructive actions in this phase |
| Primary CTA | not applicable — no new commands or buttons introduced |

**Description field replacement (D-07, D-08):**

Before: `this.description = \`@${pr.author}\``

After: `this.description = \`${pr.state} \u00b7 @${pr.author}\``

The `@` prefix on author login is preserved. The PR state indicator that was previously conveyed by the colored codicon icon is now conveyed as text in the description field.
